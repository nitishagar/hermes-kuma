Install

Requirements

  • Uptime Kuma v2 (stable 2.5.x). The upstream server does not support v1.
  • Node.js ≥ 22 on PATH. The server launches via npx -y, and npx only warns about the engines requirement — an old Node fails confusingly. Check with node --version.

Hermes Agent

hermes plugins install nitishagar/hermes-kuma --no-enable
hermes plugins enable kuma

After enabling, tools appear under the mcp__agent_plugin_kuma_… namespace and the four kuma-* skills load as agent skills. (Install takes a catalog name, Git URL, or owner/repo — a local path is rejected, so push first when testing your own fork.)

OpenClaw

openclaw plugins install git:github.com/nitishagar/hermes-kuma

OpenClaw detects the Agent Plugins layout (plugin.json marker) and maps skills plus the ku stdio MCP server. Tools register in the short ku__<tool> form.

Any MCP-capable host

Register a stdio MCP server with this command, then load the repo's skills/ directories as agent skills:

npx -y @davidfuchs/mcp-uptime-kuma@0.11.18

Verify

  1. Configure credentials (see Credentials).
  2. Ask for a monitor summary — the incident-review skill starts with one.
  3. If tools appear but error, work the troubleshooting ladder in kuma-setup (Node version, cold npx cache, missing env vars, wrong credentials, unreachable instance).
  4. If no kuma/ku tools appear at all, the plugin may not be enabled or the host blocked the spawn.

Offline cold cache: the first npx run downloads the package. On a machine that will be offline, pre-warm once while online: npx -y @davidfuchs/mcp-uptime-kuma@0.11.18 --help.
