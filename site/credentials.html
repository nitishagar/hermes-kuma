Credentials

The server reads UPTIME_KUMA_URL (always required) plus, when your instance has auth enabled, UPTIME_KUMA_USERNAME / UPTIME_KUMA_PASSWORD — or a JWT. The bundle ships no secrets and no env map. Pick a tier:

Tier 1 — guaranteed: your host's own MCP configuration

The guaranteed credential path is your host's own MCP configuration, pinning the same version (@davidfuchs/mcp-uptime-kuma@0.11.18).

Hermes

An mcp_servers entry in config.yaml whose env can reference secrets via ${env:VAR} (resolved from ~/.hermes/.env):

mcp_servers:
  kuma:
    command: "npx"
    args: ["-y", "@davidfuchs/mcp-uptime-kuma@0.11.18"]
    env:
      UPTIME_KUMA_URL: "http://your-kuma-host:3001"
      UPTIME_KUMA_USERNAME: "<your username>"
      UPTIME_KUMA_PASSWORD: "${env:UPTIME_KUMA_PASSWORD}"

OpenClaw

openclaw mcp add kuma --command npx --arg -y \
  --arg @davidfuchs/mcp-uptime-kuma@0.11.18 \
  --env UPTIME_KUMA_URL=http://your-kuma-host:3001 \
  --env UPTIME_KUMA_USERNAME=... --env UPTIME_KUMA_PASSWORD=...

Tier 2 — best-effort: ambient environment

Hosts that pass their own environment to spawned MCP servers need nothing extra — export the UPTIME_KUMA_* variables before starting the host and verify with a cheap read. This does not work on Hermes or OpenClaw (both filter ambient variables for spawned stdio servers) — use Tier 1 there.

Tier 3 — HTTP sidecar (VPS / remote agents)

Run the server's documented Docker form with -t streamable-http and point your host's MCP config at http://<host>:3000/mcp.

Warning: with MCP_AUTH_TOKEN unset there is no authentication, ALLOWED_ORIGIN defaults to *, and the endpoint has full read/write control including deleting monitors — always set a token and a narrow origin. Never expose the raw endpoint off-host unencrypted (terminate TLS in front or keep it loopback/host-internal).

2FA and API keys

2FA users: prefer a JWT — npx -p @davidfuchs/mcp-uptime-kuma@0.11.18 mcp-uptime-kuma-get-jwt <kuma-url> <username> <password> — and supply UPTIME_KUMA_JWT_TOKEN instead of username/password. Kuma's API keys will not work here: they authenticate only Kuma's /metrics endpoint, not this server's login.

Command-line hygiene: when an example would put a real secret on the command line, prefer the env-reference form (${env:VAR}) or your host's secret mechanism instead — command-line secrets land in shell history and process lists.
